# Using Ghidra names in the Obi-Wan recompile

Ghidra can identify Xbox SDK, CRT, and audio/video library functions in the
retail XBE. Feeding those names into the generated C makes call paths easier to
read and gives runtime traces useful symbols. The export contains function
addresses and names only; keep the XBE and the Ghidra project local.

## Export from the analyzed XBE

Open the analyzed `default.xbe` program in Ghidra. In Script Manager, add the
`tools/ghidra` directory from this repository to the script search paths, then
run `ExportObiwanNames.java` and choose a JSON output path. Save it outside the
Ghidra project, for example:

```text
obiwan-recomp/build/ghidra-export/functions.json
```

This script uses function entry addresses as loaded in Ghidra. The Xbox XBE
loader project must retain the executable's Xbox virtual addresses so they
match recompiler addresses.

## Regenerate with the names

From the Obi-Wan repository's Nix development shell, pass the export directory
to the generator:

```sh
python tools/generate_obiwan.py --ghidra-export build/ghidra-export
```

The pipeline filters out autogenerated names, de-duplicates valid C
identifiers, and applies only names whose entry addresses match discovered
functions. It records the resulting map and import report under
`build/obiwan-analysis/`; generated data and C remain ignored build outputs.
Without `--ghidra-export`, generation follows the original path unchanged.

The existing analyzed project currently yields 524 matching names, mostly
XDK and CRT APIs. Those labels improve navigation and diagnostics; game-owned
functions still need to be identified through call graphs, strings, and
runtime evidence. `tools/ghidra/obiwan_function_names.json` also records four
title-specific names supported by the profile-flow decompilation; the generator
checks that each address is present before applying them.
